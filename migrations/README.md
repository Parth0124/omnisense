# migrations/

*Alembic migrations for the PostgreSQL schema.*

Run from the repository root — the config path is explicit because `alembic.ini`
lives here rather than at the root:

```bash
make migrate                              # alembic upgrade head
make migration m="add signals table"      # autogenerate a revision
make downgrade                            # roll back one revision
```

| Path | Purpose |
| --- | --- |
| `alembic.ini` | Alembic config. `sqlalchemy.url` is deliberately blank. |
| `env.py` | Reads `DATABASE_URL` from the environment; imports ORM metadata. |
| `script.py.mako` | Revision template. |
| `versions/` | Generated revisions. |

## Rules

- **Always review an autogenerated migration by hand.** Alembic misses index
  changes, server defaults and type widenings, and will happily generate a
  destructive drop.
- Migrations are forward-only in shared environments. Write a new revision
  rather than editing an applied one.
- Only PostgreSQL is managed here. The Neo4j graph schema is versioned
  separately under [`graph/schema/versions/`](../graph/schema/versions/).
